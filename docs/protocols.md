# 设备协议

记录日期 2026-10-31。报告长度均包含 Windows HID 的 Report ID 字节。

## G502 X PLUS
046D:C547，MI_02/COL02，FF00:0002，Input/Output 20，Feature 0。
Report ID 11，槽位 01。Root.GetFeature(1004) 返回 Unified Battery 索引，本机 06。
调用函数 1，回复 [4] 百分比、[5] 粗档位、[6] 状态：0 放电，1/2/4 充电，3 满。
每次请求轮换 Software ID，严格匹配槽位、功能、完整地址。已知支持 1004 的 G502 不在查询失败时回退其他电池功能。
最初实测：11 01 06 1D 49 08 00 00 … → 73%。

## Nova 7 Gen 2
1038:227E，MI_03，FFC0:0001，Input/Output 65，Feature 515。
查询 00 B0 补零。Windows 回复带前导 00；归一化后 [0]=B0，[2] 百分比，[3] 状态。
状态 0 离线，1/2 充电，3 电池供电。拒绝未知状态、越界值和错误前缀。
最初实测：00 B0 03 4F 03 … → 79%。

## 北通盘古
20BC:5162，MI_04，FF80:0001，Input/Output 64，Feature 0。
厂商盘古脚本确认 Report ID 02；getBaseInfo 查询 02 15，补零至 64 字节。
仅接受 02 15 回复，[2] 百分比，[4]&0F 非零为充电。
最初实测 02 15 51 00 00 01 … → 81%；成品读取 80%。
XInput 返回 WIRED/FULL，不能作为电量。
休眠时厂商接口可能从 PnP 消失。

## MCHOSE K99 V3

USB 有线为 3837:2020，产品名为 MCHOSE K99 V3。接收器为 3837:3033，产品名为 MCHOSE K99 V3 2.4G。程序同时匹配产品名、MI_01、0001:0000、Input/Output 65、Feature 0。两者共用原有的 mchose-3033-1 设备键，有线接口存在时优先使用有线。

向该接口发送 00 55 05 00 38 38，补零至 65 字节，仅读取功能配置的第一段。首字节 00 是 Windows 给无编号 HID 报告加的 Report ID。接受 00 AA 05 开头、数据长度 56、偏移为零的 65 字节回复，并核对校验字节 [4] 等于从 [5] 起求和取低 8 位。

索引从零起算。功能配置数据从报告 [9] 开始，数据 [32] 即报告 [41]。低七位为电量百分比，最高位为充电标志。真机断电时为 64（100%，电池供电），接上供电后为 E4（100%，充电中），与 MCHOSE HUB 一致。三个配置档返回相同的电量与充电标志，程序只需读取一段。

命令 03 读的是设备信息。本机回包包含接收器的版本和名称，其中的 34 不能解释为 52% 电量。字段依据为官方 Web SDK 的功能配置解析。 [官方驱动](https://www.mchose.com.cn/) · [SDK 脚本](https://www.mchose.com.cn/cizhou/CZ_SHARED_DATA/main.b1d3fb6f68d495cc5961.js)

接收器的链路通知使用 00 FA FB 06，后续 00 表示通信停止，01 表示恢复。通知语义来自官方 SDK，程序被动监听。中断时保留缓存并暂停查询，恢复时补读。单次查询无有效回复时显示未连接，后续常规刷新仍可尝试恢复。实机熄灯和重新亮灯时未观察到链路通知，因此界面按连接状态显示。

## 静置与缓存
鼠标 15 秒无对应 Raw Input 活动后停止主动查询；盘古以厂商接口消失判断休眠或断开，接口重现后恢复。
只使用 RAWINPUTHEADER.hDevice 和 RIDI_DEVICENAME，不读取输入内容。
活动后补读，失败 / 离线 / 静置保留最后有效值，标记状态，不把旧值当实时值。
